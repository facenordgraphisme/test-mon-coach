# Technical SEO — Rêves d'Aventures (revesdaventures.fr)

Score: **35/100**

## What works

- HTTPS enforced everywhere with HSTS (`Strict-Transport-Security: max-age=63072000`).
- Clean host canonicalization at the HTTP level: `http://` → `https://` (308), non-www → `www` (307). Final serving host is `https://www.revesdaventures.fr`.
- `robots.txt` is clean and permissive (`Allow: /`, `Disallow: /api/`, sitemap declared).
- Custom 404 returns a real `404` status (not a soft-404).
- Fast TTFB (~0.26s), Brotli compression enabled, served from Vercel edge (`X-Vercel-Cache: HIT`).
- `lang="fr"` set correctly on `<html>`.
- Mobile viewport meta tag present and correct.
- Server-rendered HTML (Next.js App Router) — fully crawlable without JS execution.

## Critical Issues

### 1. Sitewide canonical tag points every page to the homepage
**Severity: Critical**

Every page on the site — including all activity pages, `/contact`, `/calendrier`, `/guide`, `/avis`, `/multi`, `/niveaux`, `/acces`, `/cgv`, `/mentions-legales`, and even the legacy `/activities/*` pages — outputs:

```html
<link rel="canonical" href="https://revesdaventures.fr"/>
```

**Verified on (all return canonical = homepage):**
`/`, `/aventures/escalade`, `/aventures/canyoning`, `/contact`, `/calendrier`, `/guide`, `/aventures/duo-activites`, `/multi`, `/niveaux`, `/acces`, `/avis`, `/cgv`, `/activities/canyoning`, `/activities/kayak-et-escalade`

**Root cause** ([app/layout.tsx:28-30](app/layout.tsx#L28-L30)):

```ts
alternates: {
  canonical: '/',
},
```

This is set once in the **root layout** metadata with `metadataBase: new URL('https://revesdaventures.fr')`. No page-level `generateMetadata` (including the shared `generateSeoMetadata()` helper in [lib/seo.ts](lib/seo.ts)) ever overrides `alternates.canonical`, so every route inherits `/` → resolves to `https://revesdaventures.fr/`.

**Impact:** This is a direct instruction to Google that every URL on the site is a duplicate of the homepage and should not be indexed independently. In practice this can suppress indexing of every activity page, the booking calendar, contact page, guide bio, etc. — pages that are the actual landing targets for "Escalade Hautes-Alpes", "Canyoning Serre-Ponçon", "Via ferrata Embrun" type queries. This is very likely the single biggest factor limiting organic visibility for anything other than the homepage/brand query.

**Fix:** Each route's `generateMetadata` must set `alternates: { canonical: <absolute-or-relative-page-path> }`. The cleanest fix is to extend `generateSeoMetadata()` in `lib/seo.ts` to accept and emit a `canonicalPath`, and pass the current route's path from every page (`/aventures/${slug}`, `/contact`, `/calendrier`, etc.). Remove the blanket `alternates.canonical: '/'` from the root layout (or leave it only as the homepage's own metadata, not inherited).

### 2. Sitemap.xml reflects the old URL structure and omits most live pages
**Severity: Critical**

`sitemap.xml` (generated by [app/sitemap.ts](app/sitemap.ts)) lists 22 URLs:

- `/`, `/activities`, `/calendrier`, `/guide`, `/contact`, `/cgv`, `/mentions-legales`
- 15 activity URLs under **`/activities/{slug}`** (e.g. `/activities/escalade`, `/activities/canyoning`, `/activities/kayak-et-escalade`, `/activities/via-ferrata-et-escalade`, …)

But the site's actual navigation and live page set use a **different, newer structure**:

- `/aventures/escalade`, `/aventures/canyoning`, `/aventures/via-ferrata`, `/aventures/velo-de-route`, `/aventures/vtt-et-vtt-electrique`, `/aventures/planche-a-voile-windsurf`, `/aventures/mono-activite`, `/aventures/duo-activites`
- `/multi`, `/niveaux`, `/acces`, `/avis`

**None of these 12 live, linked, navigable pages appear in `sitemap.xml`.**

**Root cause** ([app/sitemap.ts:9-16](app/sitemap.ts#L9-L16)): the sitemap generator queries Sanity for `activity` documents and builds URLs as `${baseUrl}/activities/${activity.slug}` — the **old** route prefix — and the static URL list ([app/sitemap.ts:18-61](app/sitemap.ts#L18-L61)) was never updated to include the new `/aventures/*`, `/multi`, `/niveaux`, `/acces`, `/avis` routes added during the rebrand.

**Fix:** Update `app/sitemap.ts` to:
1. Generate activity URLs as `${baseUrl}/aventures/${activity.slug}` (matching the live route in [app/aventures/[slug]/page.tsx](app/aventures/[slug]/page.tsx)).
2. Add static entries for `/multi`, `/niveaux`, `/acces`, `/avis`, `/aventures/mono-activite`, `/aventures/duo-activites`.
3. Remove `/activities` and the `/activities/*` entries once those routes are redirected/removed (see issue #3).

### 3. Orphaned legacy `/activities/*` routes are live and duplicate `/aventures/*` content
**Severity: High**

The old route group `app/activities/page.tsx` and `app/activities/[slug]/page.tsx` is **still deployed and returns HTTP 200** for all 15 sitemap-listed slugs (e.g. `/activities/escalade`, `/activities/canyoning`, `/activities/kayak-et-escalade`). These pages:

- Are not linked from any current navigation, footer, or page content (confirmed: no `/activities` hrefs found on `/`, `/aventures/escalade`, `/multi`, `/niveaux`).
- Are only discoverable via the stale `sitemap.xml`.
- Render the **same activities** (e.g. "Escalade") as the new `/aventures/escalade` page, with overlapping H1, schema, and topic — i.e. near-duplicate content under two different URLs.
- Ironically have **better, unique meta descriptions** than their `/aventures/*` counterparts (see on-page findings) — good copy that's now stuck on an orphaned URL.

**Fix:** Pick one canonical URL structure (the audit recommends keeping `/aventures/*`, since that's what the live navigation uses). Add 301 redirects from each `/activities/{slug}` to its `/aventures/{slug}` equivalent (and `/activities` → `/aventures` or `/`), then remove the legacy route files and their sitemap entries. Port the good meta descriptions from `app/activities/[slug]/page.tsx` (lines 54-58) into the new route before deleting it.

## Medium Issues

### 4. Canonical/OG URLs target the apex domain, which itself redirects
**Severity: Medium**

`canonical`, `og:url`, and the sitemap's `baseUrl` all use `https://revesdaventures.fr` (no `www`). But this apex URL returns a **307 redirect** to `https://www.revesdaventures.fr/` — the actual serving host. So even once issue #1 is fixed on a per-page basis, the canonical target itself is a redirecting URL rather than the final served URL. Search engines generally resolve this correctly, but it's best practice for canonical/og:url/sitemap `loc` values to point directly at the final URL (`https://www.revesdaventures.fr/...`) to avoid any ambiguity.

**Fix:** Either set `metadataBase` / sitemap `baseUrl` to `https://www.revesdaventures.fr`, or make `www` → apex the canonical direction consistently (pick one host and make every config — `metadataBase`, sitemap, robots `sitemap:` field — agree with the host that serves 200).

### 5. Missing standard security headers
**Severity: Medium**

Only `Strict-Transport-Security` is present. Missing: `X-Content-Type-Options`, `X-Frame-Options` / `frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`, and a `Content-Security-Policy`. These don't directly affect rankings but are part of Google's "Best Practices" / security signal set and protect against clickjacking and MIME-sniffing attacks.

**Fix:** Add a `headers()` function in `next.config.ts` (or `middleware.ts`) to set these on all routes.
